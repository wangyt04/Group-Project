### 2. 为什么需要生成数据

无图，三个要点，30 秒讲完：

- 内镜图像的光源**绑在相机上**，亮度同时编码了几何、材质、运动；
- 相机轨迹**受限**，没法绕着一块黏膜转；
- 同一段肠道**不可能重拍**不同光照 → **不存在天然的重光照真值**。

下游任务要数据，而这三条决定了数据只能生成。

### 3. `[可砍]` 两种"生成"的区别

- 换视角（novel view）：标准 3DGS 就能做；
- 换光照（relighting）：需要把光和组织分开。

一句话铺垫，为第 4 页做准备。时间紧就并进第 4 页。

### 4. 两条路线

🖼 `fig01_two_routes.png`

- **路线 A**（Unity / Blender）：物理正确、标签免费、可任意组合光照；但逐帧离线渲染，
  依赖解剖资产与工程，规模化慢。
- **路线 B**（高斯泼溅）：重建一次 19 分钟，之后 **5.46 ms/帧 ≈ 183 fps**，能直接吃真实视频；
  但外观是拟合出来的。
- **我们的做法：用 A 的真值去量化 B 的物理可信度。** 不是二选一。

---

### 5. 关于"高斯重建真不真实"——先澄清

无图（或放一张 L0 三行对比的局部）。**这一页很重要，不要跳过。**

- 标准 3DGS 在训练轨迹附近是**照片级**的：C3VD 上 33.90 dB，我们修复后的模型 42.5 dB。
- 真正的局限不在"像不像"，在**它表示的是什么**：
  它是**外观拟合**，不是物理模型；**光照被烤进了颜色里**（论文原话 "bake light-dependent
  effects into textures"）。
- **标准 3DGS 能做新视角，不能做新光照。** → 引出 PR-ENDO。

> 这一页是全场最容易被问住的地方。说法要准：不要说"高斯渲染不真实"。

---

### 6. PR-ENDO 的创新

🖼 可以手画一张着色公式的分解图，或直接列公式。

- 利用内镜先验：**单光源与相机共位**；
- 每个高斯带 albedo / roughness / F0，高光用 Cook-Torrance GGX；
- **diffuseMLP** `θ(l, d, n)·a/π` —— 受限轨迹下还能泛化的关键；
- 两个新损失：`L_Diffuse`（拉回经典光传输方程）、`L_Tissue`（防止光照渗进基础色）；
- 着色：`RGB = I · att(d) · (f_diffuseMLP·(1−F) + f_spec) · (n·l)`，`att(d) = 1/(1+k·d^p)`。

**记住 `att` 这个公式，第 15 页要回来算账。**

### 7. 作者承认的缺陷 + 一个没写出来的空白

- 原文：训练时间约 2× vanilla 3DGS；**very distant light sources、extreme camera rotations、
  extreme body deformations** 仍有困难；高纹理组织可能需要更复杂的 `L_Tissue`。
- **论文里没有任何重光照的定量基准** —— C3VD / RotateColon 都没有"同一帧不同光照"的真值，
  所以重光照只能定性展示。

**→ 这就是我们的切入点。**

### 8. 我们造的评估协议

无图，一张表：

| 层级 | 改什么 | 数量 |
|---|---|---:|
| L0 | 什么都不改 → **纯重建上限** | 1 |
| L1 | 强度 ×0.5 / ×2 | 2 |
| L2 | 点光 → 聚光，光束转向 | 7 |
| L3 | 光源离开相机光心 | 8 |
| L4 | 光源颜色 R/G/B | 3 |
| L5 | 光源固定在世界坐标，相机继续走 | 2 |

**强调两件事**：

1. **L0 是设计上的关键** —— L1–L5 的误差 = 重建误差 + 重光照误差，L0 只有重建误差，相减才说得清；
2. Unity 侧把阴影、环境光、间接光、tone mapping **全部关掉**，让它退化成干净的
   "单点光源 + BRDF"，和 PR-ENDO 的物理假设一一对应。

数据：1350×1080，88 训练 / 12 留出，611 条 (配置, 帧)，803 个 GT 比较，0 缺失。

### 11. 归因：23 个候选，32 项实验

无图，或者放原因评估表的截图。

- 先把 **13 个原因排除掉**：指标（重算差 0.0000 dB）、光源坐标（< 1e-6）、真值物理性
  （拟合幂次 1.99–2.02）、颜色/伽马、标定、过曝（0.12%）、阴影（0.07% 面积）、
  法线（中位 4°）、观测次数……
- **剩下一个指向同一处**。

**这一页的作用是建立可信度**：不是猜出来的，是排除出来的。

### 12. 根因：一行 CUDA 代码

🖼 `fig12_near_cull_schematic.png`

```cpp
// depth-diff-gaussian-rasterization/cuda_rasterizer/auxiliary.h:154
if (p_view.z <= 0.2f)   // 硬编码，与 znear = 0.01 无关
```

- 工作距离中位数只有 0.336 → **0.2 = 0.595 倍工作距离**；
- 画面 **17.4%** 的像素落在里面，却占 **L0 误差的 79%**、L3 的 61–92%；
- 近壁的点**从未被渲染** → 没有梯度 → 不透明度停在初值 → opacity reset 后被 prune 删掉；
- 之后近壁由后方 **2 倍远**处的一层"幕布"高斯代画。

**这是工程缺陷，不是方法缺陷。** 把这两者分开是整个归因工作的价值所在。

### 15. 没能修好的（一）：衰减公式

🖼 `fig05_attenuation_vs_inverse_square.png`

- 学到的 p ≈ 1.97 看起来很接近 2，**但那是渐近幂次**；工作距离内的局部等效幂次只有 1.14–1.82；
- 从 0.45 到 1.3 倍工作距离，物理应衰减 **8.35×**，原始 5.10×，**P1 后仍只有 5.31×**；
- **结论：是 `1/(1+k·d^p)` 这个函数形式本身的限制**，不是幕布高斯造成的
  （d→0 时它趋近常数 1，不可能复现 1/d² 的陡峭）。

正好把论文那句 "challenges with very distant light sources" **量化**了，并指出了原因。

---

### 16. `[可砍]` 没能修好的（二）：高光

🖼 `fig11_specular_and_f0.png`

- 代码 `clamp(F_0, 0, 0.035)`，而默认 `f0_init = 0.05` **高于上限** → 梯度恒为 0，
  全场 213,091 个高斯的 F0 一模一样；
- 粗糙度也全场共享，GGX 高光瓣半高半宽 **0.55°**，而法线误差中位数 **4.0°**；
- 光源右移后，Unity 的高光 96% 转移到新位置、20% 留在原处；PR-ENDO 只转移 51%、**40% 留在原处**。
- **P2 实验（f0_init 改成 0.03）：F0 确实变成 977 个不同取值，但高光一点没变强。**
  → 根因在粗糙度 / 法线精度 / 损失函数，**不在 F0 初始化**。这是一条明确的否定结论。

### 18. 结论

1. **PR-ENDO 能迁移到 VR-Caps，效果很好** —— 首次在 C3VD/RotateColon 之外、**带定量重光照真值**
   的评估；修复后重建 42.5 dB，L2 重光照 40.0 dB。
2. **补上了论文没做的基准** —— 611 条、6 个难度层级、803 个 GT 比较。
3. **最大误差源是工程缺陷**：继承自 3DGS 的 `z ≤ 0.2` 近裁剪。一行改动 = **+8.0 dB**。
   **在内镜数据上用 3DGS 系方法的人都该检查这一行。**
4. **剩下两个是真的方法局限**：衰减公式形式、高光（根因不在 F0）。
5. **诚实的边界**：重光照评估的 49 个相机**都是训练视角**（P6 未做）。L0 的 12 个留出帧是未见视角。

## 预期问题与答案

| 问题 | 回答 |
|---|---|
| 高斯重建画面不真实吧？ | 不对。训练轨迹附近是照片级的（33.9–42.5 dB）。局限在于它是**外观拟合**、光照被烤进颜色，所以改不了光，不在于画质。 |
| 你们的分数是不是高估了泛化？ | **部分是。** L0 的 12 个留出帧是真未见视角（41.68 dB），但重光照评估的 49 个相机都是训练视角。这是 P6，没做。 |
| 改一行代码就 +8 dB，是不是数据太特殊？ | 是场景特殊、不是数据特殊：内镜工作距离只有 0.336 单位，而阈值 0.2 是为室外场景定的。**任何近距离腔体场景都会踩到。** |
| 为什么不直接用 Unity 生成全部数据？ | 规模化成本和资产依赖。而且终极目标是重建**真实病人**的视频，Unity 做不到。Unity 在这里的角色是**提供真值**。 |
| 和论文的 C3VD 结果怎么比？ | 不能直接比——不同数据、不同分辨率、不同光照协议。我们的贡献是**协议**（带重光照真值）和**归因**，不是刷分。 |
| 为什么 L4（改颜色）反而增益最小？ | 因为它最简单：只缩放光源 RGB，误差基本等于 L0 的重建误差，本来就接近上限，没多少可涨的。 |
| 阈值从 0.2 改到 0.01 有副作用吗？ | 这次没观察到：点数从 21.3 万涨到 27.1 万，训练仍 30k 步收敛，所有层级都提升。不过我们只在这一个场景上验证过。 |
